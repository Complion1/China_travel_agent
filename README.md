# 中国旅行规划助手

## 在线试用

项目已部署到云服务器，无需安装即可使用。

**[开始在线试用](http://118.89.83.175:8080)** · [查看合成样例](http://118.89.83.175:8080/samples)

按页面提示补充旅行需求、确认需求并选择酒店，即可生成攻略。这是共享演示服务，有使用配额，同一时间只执行一个任务；繁忙时请稍后再试。线上服务运行的是已部署版本，可能与仓库最新代码不同。

## 项目介绍

这个项目提供一个可以自行部署的旅行规划网页。用户通过中文对话补充出行需求，确认目的地、日期和到离枢纽，选择酒店，然后由工作流研究候选地点、规划每日行程，并生成可复制或下载的 Markdown 攻略。

模型调用使用 DeepSeek，地点与路线查询通过百度地图工具完成。PostgreSQL 保存任务、执行检查点和结果。网页使用 FastAPI 与原生 HTML、CSS、JavaScript，前端文件随应用镜像一起发布。

## 使用流程

1. 在首页输入旅行需求，根据提示补充日期、枢纽和兴趣等信息。
2. 确认整理后的需求，人工选择酒店。
3. 在任务页查看候选研究和规划进度；需要补充信息时，按页面提示操作。
4. 完成后查看按日攻略、交通说明和运行统计，复制或下载 Markdown。

`/history` 显示当前访客的任务，`/samples` 提供明确标注的合成样例。刷新或关闭页面不会取消正在执行的任务。访客通过浏览器 Cookie 识别，清除 Cookie、换设备或身份到期后不能找回原访客的任务；当前身份有效期为 30 天。

## 启动

推荐使用 Docker 与 Docker Compose。应用容器采用 Python 3.12，数据库采用 PostgreSQL 16。先准备自己的 DeepSeek 和百度地图 API 凭据，以及至少 16 个字符的数据库密码。

在项目根目录将 `.env.example` 复制为 `.m14-local/config.env`，自行填写三个凭据字段，保留本机地址 `WEB_PUBLIC_ORIGIN=http://127.0.0.1:8080`。配置通过 Compose 的 `--env-file` 显式传入，网页入口不会自动读取 `.env`。

完整步骤见 [部署说明](docs/DEPLOYMENT.md)，包括构建镜像、创建暂停凭证加密密钥、首次迁移和启动。默认只在本机 `127.0.0.1:8080` 访问；公网部署使用单独的项目、配置、数据卷和密钥。

首次初始化命令只适用于新的空数据库。应用启动只检查数据库版本，迁移需要显式执行。

## 当前范围

酒店需要人工选择。旅行费用与营业信息可能尚未核验，天气交互和地图展示尚未提供，页面会显示对应限制。攻略是规划建议，不能作为价格、开放时间或交通可达性的实时保证。

同一时间只接收一个执行任务。默认限额为全站每天 200 次、每位访客每天 20 次、每个来源地址每小时 5 次，执行会消耗部署者的模型与地图额度。数据卷可用空间低于 5 GiB 时会拒绝新任务。当前地址校验支持规范的 HTTP 本机地址或 IP 地址，域名和 HTTPS 需要后续适配。

旧提示词与产物版本保留在源码中，供既有数据读取和兼容性测试使用。修改前端后，需要重新构建并更新应用镜像，线上页面才会采用修改后的资源。

## 公开文件与隐私

仓库包含代码、提示词、迁移、测试、配置样例和使用说明，不包含实际 API 凭据、数据库数据、暂停密钥、运行记录等私有部署资料。在线试用地址按维护者授权公开。公开历史经过文件筛选和身份脱敏；内部设计审批、阶段提示词及私有交付记录保留在原开发仓库。

请将自己的配置、密钥和诊断导出保存在忽略目录中。数据库与原暂停密钥需要配套备份，复制仓库不能恢复已有访客数据。
